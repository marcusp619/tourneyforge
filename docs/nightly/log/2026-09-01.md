## Addendum — second adversarial review

A second fresh-context pass over `docs/NIGHTLY.md` found 14 further defects. The
headline one indicts this log: **R1 was recorded `done` above while still listed under
Ready, and its five checks pass on an untouched tree.** Tonight's agent would have taken

nothing — the artifact's own central failure, on its own first task.

R1's checks also compared `README.md` and `CLAUDE.md` *to each other* rather than to
`package.json`, so they passed while `apps/mobile/README.md:3` still read "Expo SDK 52".
Now fixed; R1 is genuinely complete and moved to Done.

Two Protocol rules were added as a result, both general rather than task-specific:

- **Green before you start = broken task.** Run the Verify block before changing
  anything. If it already passes, the task cannot prove its Goal — record it
  `mis-specified`, propose a replacement, take the next task.
- **Assert truth, not consistency.** A check comparing two documents passes when both
  are wrong the same way. Assert against `package.json`, the schema, or the running
  server.

Most of the other 14 findings were three bugs repeated, so the fix was structural rather
than 14 patches: `scripts/verify-lib.sh` now provides the assertions, and Verify blocks
may not hand-roll `grep`. The helpers close:

- `grep -r PAT missing/dir` → exit 2, which `! grep` turned into a PASS
- `grep -q "$(command-that-returned-nothing)"` → `grep -q ""` matches any input
- `! grep PAT file` → a grep *error* read as clean

Also fixed: `git diff --name-only | grep -qv test` asserted the opposite of its comment
(it passes whenever any non-test file changed); R3 as written created a turbo dependency
cycle (`types → validators → db`) and could not compile; R4's grep banned label strings,
so renaming a label passed while the `TextInput` stayed bound to `setTournamentId`;
`pnpm dev:up` and `pnpm test:e2e` were used by tasks that never created them, in the
wrong order; G5 called `act`, which is not installed, and contained a literal
`<the same CI job command>` placeholder; `docker compose ps | grep -q healthy` matches
"unhealthy"; and the clean-checkout recipe (`git clean -xdf`) deleted the agent's own
uncommitted work including this log.
